Built on the 360 design system

As of Round 1, every template renders through the 360 by Native Instruments design system — the same skill the wider NI 360 team uses for landing pages and Meta paid social. That means the visual layer is locked: NATIVE Pro Wide Ultra display, Graphik body, the spectrum gradient, NI horizontal logo lockup, hairline borders, no shadows. Ryan only picks the words and the variant.

What’s shared

Two stylesheets in site/design-system/ drive every approach template:

  • tokens.css — brand colours, fonts, spectrum gradient, radii, line-heights.
  • ad-shell.css — ad anatomy: top label pill, oversized headline, sub, foot lockup + CTA, plus the spectrum / dark / coral / violet variants.

Update either of these and all three approach templates inherit the change. No per-template CSS drift.

What’s per-approach

Each template adds its own middle-content block on top of the shared shell:

  • A — product key-art row across the centre.
  • B — price-comparison table on a white panel.
  • C — full-bleed producer photo with a dark scrim, quote bottom-left.

Each lives in its own file as a small <style> block before the gallery markup. Rebuild from scratch if the brief changes — reskinning is faster than refactoring.

How to populate a template

  1. Open the matching HTML template in site/templates/.
  2. Edit the CONFIG block at the bottom of the file — headline, sub, CTA, label pill, product slugs (or producer fields for C).
  3. Voice-check the copy against design-system/style-guide rules: sentence case, no em dashes (en dash with spaces is fine), no exclamation points, no clichés (elevate, supercharge, unleash, cutting-edge, innovative). The style guide skill is in the design-system folder.
  4. Pick the variant if changing from default: add spectrum, dark, coral, or violet as a class on the .ad elements. (A defaults to dark; B defaults to spectrum; C is photo-backed.)
  5. Drop image assets into the right spot:
    • Approach A — product key-art is already in design-system/assets/products/; pick slugs in CONFIG.products.
    • Approach C — producer portrait goes in templates/images/.
  6. Open the HTML file in a browser to preview all three ratios. The fonts load locally from design-system/fonts/.
  7. Click Download PNG on each ratio — html2canvas renders at exact 1080px output and saves with the framework filename pattern.
  8. Cross-check the asset tracker. Hand off to Leo for Smartly.
Filename pattern auto-applied by the download button: NI360_[A|B|C]_[ratio]_[audience]_[round].png, e.g. NI360_A_4x5_broadtrial_R1.png. Leo verifies before trafficking.

Legal flags (by approach)

  • A — pro toolkit: product key-art is sourced from the design-system folder (already cleared for marketing use). Any artist endorsement still needs consent.
  • B — price anchor: individual plugin prices must be verified at go-live. The phrase “all future updates included” needs legal approval. The comparison total has to round cleanly or it reads as dodgy.
  • C — producer quote: the quote must be attributed, verified, and consented in writing. Credits must be accurate. The star rating must be sourced from a verifiable platform (Trustpilot, G2, Google Reviews) — never fabricated. UGC consent documentation has to be on file before ship.
